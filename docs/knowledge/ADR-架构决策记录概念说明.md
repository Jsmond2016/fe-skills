# ADR（架构决策记录）概念说明

> **编写时间**：2026-05-26；**使用模型**：DeepSeek V4 Flash；**用户**：Jsmond2016

---

## 什么是 ADR

ADR 是 Architecture Decision Record（架构决策记录）的缩写。一种轻量级文档实践，用于记录项目中**为什么**做了某个架构决策。核心思路来自 Michael Nygard 于 2011 年发表的博客文章。

## 典型结构

- **标题**：简短描述决策（如"采用 PostgreSQL 作为写模型数据库"）
- **状态**：提议 / 接受 / 废弃 / 被取代
- **背景**：为什么需要做这个决策
- **方案**：选择了哪个方案
- **放弃的方案**：有哪些替代方案及选择理由
- **影响**：决策带来的正向与负向后果

## 使用动机

- 半年后回头看代码，能知道"当时为什么这么写"
- 新人 onboarding 不用到处问人
- 避免团队反复讨论同一个问题

## grill-with-docs 中 ADR 的触发条件

仅在同时满足以下三个条件时才提议创建 ADR：

1. **难以逆转** — 以后改主意成本很高
2. **不看上下文会困惑** — 未来的人会问"为什么这样"
3. **真的有取舍** — 存在多个可选方案且有合理理由选了一个

不符合任何一条则不写，避免文档噪音。
