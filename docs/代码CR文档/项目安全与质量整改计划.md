## 背景与目标

本计划承接 2026-07-11 全量代码审查结果，目标是消除 Skill 管理脚本中的命令注入、路径穿越和同步误删风险，并补齐 manifest 一致性、YAML 校验及自动化测试门禁。

## 整改范围

| 阶段 | 问题 | 主要改动 | 验收标准 |
|:----:|:-----|:---------|:---------|
| P0（已完成） | Shell 命令注入 | 使用无 Shell 的参数数组执行外部命令；校验仓库名和 URL | 特殊字符输入被拒绝，测试覆盖 |
| P0（已完成） | Skill 路径穿越 | 统一名称和目录边界校验 | `../`、绝对路径及非法名称均被拒绝 |
| P0（已完成） | 同步误删 | 仅清理指向当前源目录的失效符号链接 | 普通目录、文件及其他来源链接保持不变 |
| P1（已完成） | URL 来源字段不一致 | 统一读取 `source`，兼容历史 `sourceUrl` | 不同来源的同名 Skill 无法静默覆盖 |
| P1（已完成） | manifest 清理不完整 | 删除 Skill 时同步处理 URL/GitHub 两类来源 | 删除后状态清单无孤儿记录 |
| P1（已完成） | YAML 校验失真 | 使用 `yaml` 解析 frontmatter 并校验字段类型 | 多行描述被正确解析，畸形 YAML 校验失败 |

| P2（已完成） | 更新残留文件 | 改为同盘临时目录校验后替换，失败时恢复旧目录 | 上游删除的文件不在本地残留 |

## 实施顺序

1. 建立共享安全工具和回归测试。
2. 改造安装、更新、删除、转换脚本的输入及路径处理。
3. 收紧仓库端与消费端同步删除逻辑。
4. 修复 manifest 和 YAML 校验器。
5. 更新 CI、文档与跨会话 Memory，执行全量验证。

## 约束与回滚

- 不改变现有 CLI 的正常参数形式。
- 不主动下载或更新第三方 Skill，避免引入非确定性内容变化。
- 每阶段均以 `npm test`、Shell 语法检查和同步 dry-run 验证。
- 若兼容性测试失败，保留旧数据格式的只读兼容，但不保留不安全执行路径。
